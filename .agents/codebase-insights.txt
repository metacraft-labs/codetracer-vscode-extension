- CtEventKind numeric values are defined in libs/codetracer/src/common/ct_event.nim; ct_vscode.js does not export them. We currently rely on CtCompleteMove=8 and CtUpdatedFlow=57 for VSCode-side flow decorations. InternalLastCompleteMove = 66 (not 64 — CtUpdateExpansion=64 and CtUpdateExpansionResponse=65 were added).
- Extension webview panel mount flow: each panel's `bindXxxExtensionHost` proc (in calltrace.nim, state.nim, scratchpad.nim, terminal_output.nim) is called from `makeXxxComponentForExtension` on DOMContentLoaded. It calls the panel's `initXxxVM()` or `tryMountIsoNimXxxPanel()` directly — NOT `host.innerHTML = ""`. The innerHTML clearing was replaced because it left the container empty instead of mounting the IsoNim view.
- `tryMountOriginSidePanel()` in state.nim's `initStateVM` is guarded with `when not defined(ctInExtension):` because it appends a floating aside to document.body expecting a full desktop DOM — extension webviews have a minimal, panel-only DOM and must not call it.
- `IndexDefect: index -1 not in 0 .. N` in the webview: caused by `data.activeSessionIndex = -1` (no active session sentinel) being used to index `data.sessions[]` via the `data.services` / `data.dapApi` templates in types.nim. Fixed in types.nim:2587-2601 by guarding `if data.activeSessionIndex >= 0:` before the `data.services` access inside the CtCompleteMove and CtUpdateExpansionResponse dapApi handlers. See also shortcuts.nim:667 for the same guard pattern.
- WDIO (WebdriverIO) with wdio-vscode-service is used for E2E UI tests (same pattern as vivafolio-vs-code). Tests require VS Code Insiders and run via `npm run test:wdio`. The Stylus trace test (`test:wdio:stylus`) requires a pre-recorded fixture generated by `scripts/prepare-stylus-fixture.sh`.
- The extension's `tsconfig.json` only compiles `src/`; WDIO test files under `test/wdio/` are compiled by WDIO's built-in TypeScript support (tsx). A separate `tsconfig.wdio.json` exists for IDE support only.
